# Deployment

Target setup: **Render** for the API and PostgreSQL (`render.yaml` blueprint), **Vercel** for the React app (`frontend/vercel.json`), **PayMongo** test mode for deposits, and any SMTP provider (for example Brevo, Mailgun or Resend) for email.

```
Vercel (React SPA)  ──HTTPS + WSS──►  Render web service (Docker, Spring Boot)  ──►  Render PostgreSQL 16
                                               │  ▲
                                   SMTP ◄──────┘  └──── PayMongo webhooks
```

## 1. Push the repository to GitHub

CI (`.github/workflows/ci.yml`) runs on every push and PR to `main`: backend checkstyle + tests + coverage gate, frontend lint + typecheck + tests + build, then both Docker images.

## 2. Backend and database on Render

1. In Render: **New → Blueprint**, then select the repository. Render reads `render.yaml` and proposes:
   - `queueup-db`: PostgreSQL 16 (free plan)
   - `queueup-api`: Docker web service built from `backend/Dockerfile`, health check `/actuator/health`
2. Fill in the variables marked `sync: false`:

   | Variable | Value |
   |---|---|
   | `FRONTEND_ORIGIN` | Your Vercel URL, e.g. `https://queueup.vercel.app` (comma-separate several) |
   | `MAIL_HOST`, `MAIL_PORT`, `MAIL_USERNAME`, `MAIL_PASSWORD`, `MAIL_FROM` | Your SMTP provider's credentials |
   | `PAYMONGO_SECRET_KEY` | `sk_test_...` (step 4) |
   | `PAYMONGO_WEBHOOK_SECRET` | `whsk_...` (step 4) |

   Set automatically: `DATABASE_URL` (Render's `postgres://` URL; the app converts it to JDBC), `DB_USER`, `DB_PASSWORD`, `JWT_SECRET` (random 256-bit), `SPRING_PROFILES_ACTIVE=prod`, `SEED_DEMO=true`.
3. Deploy. Flyway creates the schema on first start and the seeder loads the demo businesses. Check `https://<api>.onrender.com/actuator/health` returns `UP` and `https://<api>.onrender.com/swagger-ui` loads.
4. After the first successful deploy you may set `SEED_DEMO=false`. The seeder is idempotent either way.

> Free Render instances sleep after inactivity; the first request after a nap takes 30–60 s. WebSocket clients reconnect automatically.

## 3. Frontend on Vercel

1. **Add New → Project**, import the repository, set **Root Directory** to `frontend`. The framework is detected as Vite; `vercel.json` adds the SPA rewrite and caching headers.
2. Environment variable: `VITE_API_URL = https://<api>.onrender.com` (no trailing slash). The WebSocket URL is derived from it (`wss://<api>.onrender.com/ws`).
3. Deploy, then make sure the resulting URL is in the backend's `FRONTEND_ORIGIN` (it controls both CORS and the allowed WebSocket origins). Redeploy the backend if you change it.

## 4. PayMongo (test mode)

1. Create an account at https://dashboard.paymongo.com and stay in **Test mode**.
2. **Developers → API keys**: copy the **secret key** (`sk_test_...`) into `PAYMONGO_SECRET_KEY` on Render.
3. **Developers → Webhooks → Create webhook**:
   - URL: `https://<api>.onrender.com/api/webhooks/paymongo`
   - Events: `checkout_session.payment.paid`
4. Copy the webhook's **signing secret** (`whsk_...`) into `PAYMONGO_WEBHOOK_SECRET` and redeploy.
5. Test: sign in as `customer@demo.queueup`, book at **Sanare Dental Clinic** (20% deposit), pay with a PayMongo test card or GCash test flow. The booking switches to **Confirmed** within seconds and a confirmation email is sent.

Without keys, deposit bookings stay "Awaiting deposit" and are released after 15 minutes; the deposit-free demo shop (Kanto Cuts) works fully.

## 5. Email

Any SMTP server works. Typical values: `MAIL_PORT=587`, `MAIL_SMTP_AUTH=true`, `MAIL_STARTTLS=true`. Use a `MAIL_FROM` address on a domain verified with your provider.

## Environment variables reference

| Variable | Required | Default (local) | Purpose |
|---|---|---|---|
| `DATABASE_URL` | yes | `jdbc:postgresql://localhost:5432/queueup` | JDBC or `postgres://` URL |
| `DB_USER`, `DB_PASSWORD` | yes | `queueup` | Database credentials |
| `JWT_SECRET` | yes (prod) | dev-only fallback in `dev` profile | Base64, at least 256 bits (`openssl rand -base64 48`) |
| `FRONTEND_ORIGIN` | yes | `http://localhost:5173` | CORS and WebSocket allowed origins (comma-separated) |
| `MAIL_HOST`, `MAIL_PORT`, `MAIL_USERNAME`, `MAIL_PASSWORD`, `MAIL_SMTP_AUTH`, `MAIL_STARTTLS`, `MAIL_FROM` | for email | Mailpit | SMTP |
| `PAYMONGO_SECRET_KEY`, `PAYMONGO_WEBHOOK_SECRET` | for deposits | empty | PayMongo |
| `SEED_DEMO` | no | `false` (`true` in compose) | Load the demo businesses |
| `PORT` | no | `8080` | HTTP port (Render sets it) |
| `VITE_API_URL` | frontend build | empty (same origin) | API base URL for the SPA |

## Production checklist

- [ ] `JWT_SECRET` generated by Render (never reuse the compose default)
- [ ] `FRONTEND_ORIGIN` lists only your real frontend URL(s)
- [ ] PayMongo webhook points at `/api/webhooks/paymongo` with the matching signing secret
- [ ] SMTP sender domain verified
- [ ] `/actuator/health` is `UP`; other actuator paths return 403
